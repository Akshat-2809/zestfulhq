# Zestful — zestfulhq.com

Production site for Zestful: a private space to process your thoughts. It's a port of the approved homepage design plus the early-access backend.

Everything lives in one Next.js 16 app in [`web/`](web/). The forms are handled by **Server Actions** in the same app, so there is no separate API service. They write to Postgres (Neon) and send emails through Resend. This is the same setup as classofone.

## The writing pad is private

What's typed into the hero pad lives in the `Pad` component's state. `readMood` runs in the browser, and nothing is stored or sent. `/privacy` promises this, so keep it true: if the pad ever saves or sends anything, the policy has to change first.

## Local setup

Requirements: Node 20.9 or later, and a Postgres database.

```bash
cd web
npm install
cp .env.example .env.local      # then fill in the values
npm run db:migrate              # creates the early_access and contact_messages tables
npm run dev                     # http://localhost:3000
```

Postgres for local work, pick one:

- **Docker:** `docker run --name zestful-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=zestful -p 5432:5432 -d postgres:17`. This matches the default `DATABASE_URL` in `.env.example`.
- **Neon:** create a free project and use a dev branch's connection string.

If `RESEND_API_KEY` is empty, the forms still work and the emails are skipped with a log line.

## Environment variables

| Variable | Required | Notes |
|---|---|---|
| `DATABASE_URL` | yes | Postgres connection string. Use Neon's **pooled** URL on Vercel. Without it, the forms show an error asking people to email instead. |
| `IP_HASH_SALT` | yes in production | Random string (`openssl rand -hex 32`). IPs are stored only as salted hashes, for rate limiting. |
| `RESEND_API_KEY` | for email | From resend.com → API Keys. |
| `EMAIL_FROM` | for email | `Zestful <hello@zestfulhq.com>`. The domain must be verified in Resend. |
| `NOTIFY_EMAIL` | for email | Inbox that receives each new signup and contact message. |
| `NEXT_PUBLIC_SITE_URL` | no | Defaults to `https://zestfulhq.com`. Used for canonical URLs, sitemap and OG tags. |

## How the "Keep me a page" form works

1. The form posts to the `requestEarlyAccess` Server Action (`src/app/actions/earlyAccess.ts`) with `useActionState`: the email, and the honeypot `website`.
2. If the honeypot is filled, the action returns a normal-looking success and stores nothing.
3. zod validates the input. The email is trimmed and lowercased.
4. Rate limit: 10 per IP per hour, counted in Postgres (indexed on `ip_hash, created_at`). This works across serverless instances.
5. The row goes into `early_access`: `id, email, created_at, ip_hash, user_agent`. Email is unique. A duplicate is treated as success, with no error and no second email.
6. Both emails are sent with `after()`, once the response has gone out: the thank-you and the notification to `NOTIFY_EMAIL`. An email failure is logged and never fails the signup.
7. UI states: idle → submitting (button disabled + spinner, screen-reader announcement) → success ("Thank you. Your page is waiting.") or error (next to the field, keeping what the person typed).

`GET /api/waitlist/count` returns `{ count }`, cached for 60 seconds. It's for the founder and isn't linked anywhere on the site.

## How the contact form works

`/contact` uses the same pattern. `ContactForm` posts to the `sendContactMessage` Server Action, with the same honeypot, zod validation (name, email, a message of 10 to 5,000 characters) and a limit of 5 messages per IP per hour. Messages go into `contact_messages`. The message is forwarded to `NOTIFY_EMAIL` with reply-to set to the sender, and the sender gets a short acknowledgement.

## Deploy to Vercel

1. Push the repo to GitHub, GitLab or Bitbucket, then in Vercel choose **Add New → Project** and import it.
2. Set **Root Directory** to `web`. The framework preset (Next.js) and the build command are detected automatically.
3. **Database:** Project → **Storage** → **Create Database** → **Neon (Postgres)**, and connect it to the project. This adds `DATABASE_URL` to the environments you choose.
4. Add `IP_HASH_SALT`, `RESEND_API_KEY`, `EMAIL_FROM` and `NOTIFY_EMAIL` under Settings → Environment Variables, for Production (and Preview if you want previews to send emails).
5. Run the migration once against the production database, from your machine:
   ```bash
   cd web
   DATABASE_URL="<Neon connection string from Vercel>" npm run db:migrate
   ```
   Repeat this whenever you add a migration.
6. Deploy. Preview deployments serve a `Disallow: /` robots.txt, so they stay out of search results.

## Connect the domain

1. In Vercel: Project → **Settings → Domains** → add `zestfulhq.com`, then `www.zestfulhq.com`, and choose to **redirect `www` to the apex**.
2. Vercel shows the exact DNS records to create (typically an **A** record for `@` and a **CNAME** for `www`). Add them at your domain registrar, removing any default "Parked" records first.
3. Wait for both domains to show **Valid Configuration**. HTTPS certificates are issued automatically.

To send email: in Resend, **Domains → Add Domain** → `zestfulhq.com`, add the DNS records it lists, click **Verify**, and set `EMAIL_FROM` to an address on that domain. Resend only sends. To *receive* mail at hello@zestfulhq.com, set up a mailbox provider (Google Workspace, Zoho, etc.) and add its MX records.

## Fidelity notes (vs. the approved design, `Main.dc.html`)

Compared side by side in Chrome at 1440px and 390px, with reduced motion so animations don't skew the numbers.

Intentional differences:
- **Early access is real.** The design's form only flipped to a thank-you. It now validates and stores, and has a one-line consent note linking to the privacy policy, which makes that card's text slightly longer.
- **Founder photo and LinkedIn** replace the `[Founder photo]` placeholder, which makes the story section 32px taller.
- **Pages added:** Privacy, Terms and Contact are real pages, linked from the footer. The design pointed Privacy and Terms at `#write`. Their look is new, built from the design's tokens.
- **A real navbar replaces the design's corner links.** Wordmark left, section links centred with an underline that follows the section being read, "Build with us" as a button on the right, on a blurred paper bar. It still hushes while writing. On phones (960px and below) it shows the wordmark and the button only, as the design's corners did.
- **Crossed-out words fit on one line on phones.** In the design, the two longest wrap at 390px and the strike falls between the lines.
- **Contrast fixes:** the pad's placeholder (2.67:1 → 4.51:1), the crossed-out words (3.10:1 → 3.78:1), and the small text on the tinted cards, which on the early-access card has to survive every mood colour.
- **Fade-ins** start at opacity .01 instead of 0, so Chrome can count the hero text as the LCP element. It looks identical.
- **Without JavaScript,** the poll bars and the hidden story and "isn't" elements show in their final state.
- **Reader swap** restarts its animation with a React `key` instead of alternating two identical classes.
